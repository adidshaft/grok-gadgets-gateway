# Protocol 0.1.0 (canonical)

Device transport: LF-delimited UTF-8 JSON; one request produces one response. Maximum frame **2048 bytes including LF**. No unsolicited gateway messages. TCP defaults to 127.0.0.1:8765; it is loopback only and unencrypted, for a same-host agent or USB bridge. Remote/Wi-Fi public transport is not implemented. Persist the socket and poll every 100–500 ms, including when idle; 15 seconds without a request closes the session.

See device-request.schema.json, device-response.schema.json and fixtures/device-transcript.json. First request is hello with protocol_version 0.1.0, device descriptor and per-device token. USB bridge supplies token, so firmware excludes it. Device IDs use `[A-Za-z0-9][A-Za-z0-9._:-]{0,63}` matched against the whole string (the schema anchor `$(?![\s\S])` rejects a trailing LF); tokens contain >=16 characters. Capabilities are string names; rgb.set has canonical strict {r,g,b: integer 0..255, on:boolean} arguments. JSON integers are type-strict everywhere the gateway validates: `255.0` and booleans are not integers. Custom capability arguments are JSON objects; devices must validate their own capability-specific inputs. Inline custom command schemas are validated as described below.

A poll delivers at most one command (fits firmware framing). Commands have command_id, capability and arguments. On completion acknowledge with status executed or failed and current state; failed requires error. Acknowledgement is a report of execution, never proof of physical effect. Events identify boot-unique event_id, name, data and optional observed_at; button requires exactly {pressed:boolean}. The gateway accepts repeated identical event IDs as duplicates and rejects changed data. Report current state separately or in ack. observed_at is device time when supplied; gateway received_at is authoritative arrival time. Reconnect supplies a fresh gateway session; boot_id distinguishes device reboot. Replaced sessions cannot write.

Gateway command status: accepted, dispatched, executed, failed, timed_out, unconfirmed. Duplicate command_id with identical device/capability/arguments returns the original result while retained (128 commands). Changed parameters conflict. Timed-out or disconnected dispatched commands stay unconfirmed; late acknowledgement cannot turn them into successful commands. Commands are never replayed into a new session. Devices should deduplicate commands within a boot; this is bounded retry safety, not durable exactly-once delivery.

Events retain the last 128 entries. Cursor `<gateway epoch>:<sequence>` is global to this process. Initial null cursor reads retained history and reports history_lost when earlier history was dropped. Invalid/future cursor, dropped history and previous-server epoch return explicit errors; cursor in error message is not a recovery contract—call again with null cursor to establish a new baseline. Device filtering advances next_cursor over all scanned events. Event identifiers are deduplicated over the last 256 newly accepted IDs for each registered device’s current boot; one busy device cannot evict another device’s window. Identical retries do not refresh retention. Reconnecting with the same boot_id preserves that window; changing boot_id discards the retired boot window. Returning later to an old boot_id starts a fresh window, so devices must use a fresh boot identity on reboot. At most 64 devices are registered per process (including disconnected devices); each has one current-boot window, so duplicate bookkeeping is bounded at 16,384 IDs with no retired sessions or boots retained. Repeated IDs outside the window may appear again. Global readable history is independent of duplicate retention and remains bounded at 128 events. State is reported, with received timestamp and freshness (fresh/stale/offline); default stale threshold 10 seconds. No persistence across gateway restart.

TCP error response: {ok:false,error:{code,message}}. Important codes: invalid_request, protocol_mismatch, unauthorized, revoked, stale_session, unknown_command, duplicate_conflict, busy, unavailable. Token failures never echo input. Revocation is reloaded from the credential file on each request. Reconnect uses a capped backoff in SDKs; never retry a physical action under a new command ID merely because acknowledgement was lost.

Optional device.capability_schemas maps custom capability names to inline JSON Schema Draft 2020-12 objects. No $ref or $dynamicRef is allowed; rgb.set always uses the canonical RGB schema. A name is an event when it is the reserved name button or history_lost, or when its inline schema contains `"x-grok-gadgets-kind": "event"`. state is a read through gadgets_get_state. Events and state are not commands: discovery keeps the original capabilities list, adds command_capabilities and event_capabilities, and returns capability_contracts only for command names. An event message whose name is a command capability is rejected. The reserved capability name history_lost is that classification; the history_lost boolean on an event read is a separate cursor flag. Custom names without an event annotation remain commands for compatibility with string-only SDK clients; custom commands without a schema use object arguments and require device-side validation. Linux device custom events use an object schema with that annotation and are not commands. Optional schemas extend the locked contract without breaking string-only C124 clients. The annotation is not a new frame field. Wire format stays 0.1.0. Keep the entire hello within 2048 bytes.
